# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Developers and self-hosting operators coordinating authorized AI accounts, local model servers, and remote coding agents. The primary operator returns after leaving an interactive chat and needs exact current state without reconstructing worker transcripts.

## Product Purpose

One gateway and administrative control plane for provider access, distributed tasks, durable supervision, and resource visibility. Persistent job ownership belongs to the backend rather than the initiating conversation.

## Operating Context

Desktop or small-server installation; MCP clients including Claude Code and Codex; LightSprint workspaces; three tailnet-connected Oracle model hosts. Provider quotas, active inference, occupied sessions, and concurrency limits are separate measurements.

## Capabilities and Constraints

Existing gateway OAuth, credential pooling, account affinity, and tool policies are preserved. The integration branch has verified small multi-account text jobs and graceful runtime restart reconciliation. Full generic coding orchestration, automatic paid recovery, deployment, all-client registration, and new branding remain incomplete. No undocumented web-chat wake protocol, invented credit conversions, fake traffic, or fabricated capacity.

## Brand Commitments

The user requests a substantive high-end redesign, its own logo, cohesive theme, and collateral, with LightSprint Claude Opus 5.5 as design lead. Token2OAuth compatibility must remain. Final product name and visual direction are open. The present dashboard is an anti-reference for visual richness, not a model to imitate.

## Evidence on Hand

Dated repository evidence in docs/evidence and implementation checkpoints. Private account balances and identifiers stay outside version control. Runtime data is required for operational charts; synthetic concept data must be labeled.

## Product Principles

- Useful autonomy with explicit permissions and resource ceilings.
- Preserve recoverable state and visible ownership across client exits.
- Show observed facts, estimates, unknowns, and unsupported capabilities distinctly.
- Use economical local work where useful; do not fill slots merely because available.
- Make the infrastructure powerful and everyday operation simple.

## Accessibility & Inclusion

Responsive keyboard-accessible web UI, clear focus, readable contrast, reduced-motion support, and honest loading, empty, and error states.
