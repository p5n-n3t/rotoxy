# Offline release artifact verification

Run `node scripts/verify-release.mjs` from a clean checkout after installing the lockfile-pinned development dependencies in the normal development environment. The verifier itself never installs dependencies. It requires Node.js 22+, Python 3.11+, npm, tar, and the local TypeScript compiler. If `node_modules/.bin/tsc` is absent, it exits with a prerequisite message; do not treat a dependency-free `npm pack --ignore-scripts` archive as a complete release.

The verifier creates a mode-restricted temporary directory, stages only package/build inputs, runs the existing TypeScript build there with npm network access disabled, packs the built package with lifecycle scripts suppressed, and inspects both npm's inventory and the actual `.tgz`. It checks every generated `dist/` file, the `monitor-workforce.mjs` entry and compiled modules it imports, all packaged Snooze Python sources, the Oracle/guidance/credit modules, dashboard assets and notices, absence of development/private-config paths, and consistency between the tarball and npm inventory. It extracts the archive under the temporary directory and imports the key packaged Python modules with user-site imports disabled. It removes the temporary directory on success or failure.

This is an offline packaging and import check. It does not install the archive, start Token2OAuth or its monitor, read private operator configuration, call a provider, validate live account/session access, test a deployment or rollback, establish quota/balance, or prove provider concurrency. A passing result supports artifact completeness and local importability only. No live deployment or rollback was run for this audit.

## Evidence and remaining gaps

The current checked-in runtime enables job dispatch only when explicitly configured with `serve --supervisor-config`. The strongest direct overlap evidence is **two simultaneously observed running sessions** ([2026-10-10 overlap evidence](evidence/2026-10-10-lightsprint-overlap.json); additional run detail is in [the distributed-job evidence](evidence/2026-10-10-distributed-job.json)). This is the verified overlap count, not a provider capacity measurement. **24-worker and 35-worker concurrency remain unknown and untested**; a 35-task test under a local three-worker cap does not establish a 35-way peak. Provider slot limits, remaining credit balances, and spending bounds remain unknown. Reported session-cost deltas are provisional telemetry, not invoices or verified debits.

`supervisor/snooze/credit_ledger.py` is included and import-checked, but remains standalone and is not wired into dispatch reservations. Unknown quota can be explicitly allowed by the current strict config; that acknowledgement does not create an account budget. Live provider compatibility, production enablement, operational backup/rollback, and actual host-specific service-manager behavior still require a separately authorized, controlled release exercise. See [deployment and rollback notes](deployment/unified-supervisor.md).
