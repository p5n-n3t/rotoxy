# Swiss Army roadmap: complete the core before adding breadth

As of 2026-10-12. Priorities distinguish work in this repository from a possible ROTOXY integration. “Reuse” names present code; it does not imply the listed behavior is complete end to end. ROTOXY facts remain assignment-brief claims until its local source is reviewed.

## Next three implementations

1. **Wire the verified resource gate.** Connect strict native-unit snapshots and positive operation caps to every paid worker claim. Produce a no-dispatch dry-run receipt; unknown evidence must deny dispatch or hand off. Add isolated SQLite tests for absent, stale, over-bound, and ambiguous reservations. Do not enable paid execution with missing provider evidence.
2. **Complete the trusted local action boundary.** Implement and test a fixed-command adapter around the registered-session `ResumptionBroker`: exact project/account/session binding, fixed argv, `shell=False`, timeout/output caps, durable accepted/rejected/ambiguous receipts, and restart/idempotency behavior. Use a fake executable and temporary directories; keep actual provider CLIs disabled until their installed version and official resume contract are verified.
3. **Finish one headless recovery vertical slice.** Connect a synthetic monitor event through `recovery_service` to owner-scoped handoff and, only after steps 1–2 pass, a feature-flagged adapter. Verify duplicate events, crash between receipt/ack, operator approval, and no replay after ambiguity. Run no real paid session for this acceptance.

Defer recipes, catalog breadth, large crawls, and a second model router until these three work end to end. First inspect ROTOXY locally; its claimed model gateway and registry could make duplicate implementation needless.
