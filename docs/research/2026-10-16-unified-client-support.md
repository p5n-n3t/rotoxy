# Unified client support and Nebius preset research

**Checked:** 2026-10-15 UTC. Sources below are first-party vendor docs or product configuration.

## Findings

| Client / surface | Support label | First-party evidence and implication |
| --- | --- | --- |
| Warp Terminal / Warp Agent | **Documented, OpenAI Chat Completions** | [Custom inference endpoint](https://docs.warp.dev/agents/inference/custom-inference-endpoint/) accepts an arbitrary OpenAI-compatible base URL exposing `POST /v1/chat/completions`; user supplies model IDs, which appear in the picker. Warp routes requests through its servers, so the endpoint must be publicly reachable; localhost/private addresses are rejected. This is a protocol requirement, not proof that any URL is compatible. |
| Warp BYOK / subscriptions | **Separate documented auth paths** | [BYOK](https://docs.warp.dev/agents/inference/bring-your-own-api-key/) documents OpenAI, Anthropic, and Google provider API keys. Warp separately supports a ChatGPT subscription for eligible OpenAI models in the Warp app, and a SuperGrok subscription; it explicitly does not support a Claude consumer subscription. Do not treat a consumer plan login as an API key for a custom endpoint. |
| Claude Code root MCP | **Documented, remote HTTP MCP + OAuth** | [MCP reference](https://code.claude.com/docs/en/mcp) documents remote HTTP MCP OAuth and user scope: `claude mcp add --transport http --scope user <name> <url>`. User-scope config lives in `~/.claude.json`, is private to that user, and is available across that user's projects. A server returning 401/403 before sign-in is surfaced in `/mcp` for OAuth. The same page calls SSE deprecated and recommends HTTP where available. MCP OAuth authenticates tools; it is separate from model-provider billing/auth. |
| Codex CLI custom provider | **Documented, Responses API only** | [Current config reference](https://developers.openai.com/codex/config-reference/) defines `model_providers.<id>.base_url`, `env_key`, and optional `model_catalog_url`; `wire_api` currently supports only `responses`. The catalog URL is for a Codex-native catalog, not a promise of generic `/v1/models` discovery. An arbitrary host is usable only if it implements Codex's documented Responses protocol and auth expectations. `env_key` means a provider API key supplied through an environment variable; it does not turn a ChatGPT consumer login into API credentials. |
| OpenCode custom provider | **Documented, OpenAI-compatible Chat Completions** | [Provider docs](https://opencode.ai/docs/providers/) support `options.baseURL`, `npm: "@ai-sdk/openai-compatible"`, and a `models` map of upstream model IDs and display names. The example says IDs should match those returned by that server's `GET /v1/models`; configuration is explicit and not a universal auto-discovery promise. |
| Nebius Token Factory | **Fixed endpoint observed; protocol compatibility unverified** | The first-party [Token Factory code-sample page](https://tokenfactory.nebius.com/docs) publishes `https://api.tokenfactory.nebius.com/v1/` as its default sample endpoint, with regional endpoints in the same `codeSampleEndpoints` config. This is the best current fixed vendor preset candidate. The page inspected did not establish Chat Completions, Responses, or generic model-list compatibility; do not market it as plug-and-play OpenAI-compatible until those routes/auth are verified. |

## Product integration guidance

The current product wiring described for this assignment is `/root/mcp` on Cloudflare-buffered SSE and `/root/v1` on Ollama. Keep these as separate surfaces: MCP OAuth is tool-server authentication, while model APIs use provider-specific request protocols and credentials.

1. For a Claude Code global connection, expose a remote HTTP MCP endpoint with an OAuth flow and publish the user-scope `claude mcp add --transport http --scope user ...` command. Current SSE behavior alone does not prove OAuth interoperability; Claude Code's current docs prefer HTTP and deprecate SSE.
2. Warp and OpenCode custom endpoints need OpenAI Chat Completions behavior and a model ID the client can select. Preserve an explicit model list (or document manual model IDs); don't infer support merely from an `/v1` prefix or an Ollama route.
3. Codex CLI needs a separate Responses-compatible route/provider if the product wants native Codex CLI support. A Chat Completions-compatible `/v1` alone is insufficient according to Codex's current `wire_api` reference.
4. If adding the next fixed vendor preset, call it **Nebius Token Factory** and use the published default URL above. Treat the URL as vendor configuration, not proof that the current root model adapter can speak its API. Verify auth, model IDs/listing, and the expected request/stream protocol before claiming compatibility.

Do not conflate a client subscription with API access. Warp documents some product-specific consumer subscription integrations, while custom model endpoints and provider BYOK use provider credentials. Claude Code's remote MCP OAuth flow is another independent credential boundary. No live model request, API key, or account was used for this research.
