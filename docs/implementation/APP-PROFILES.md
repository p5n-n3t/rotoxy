# Profile and Ollama credential management

Base `origin/main`: `15767e1c31410bc9125f543c53d372fe8e865efb`. Branch: `codex/rotoxy-profile-edit-20261015`.

`CodexProfiles` exposes `updateProfile(id, { label })`, `renameProfile(id, label)`, and `removeProfile(id)`. Edits preserve profile ID, private `CODEX_HOME`, timestamps other than `updatedAt`, and saved thread ownership. Removal rejects a pending device login, an in-flight profile operation, or any saved thread ownership because the current registry does not distinguish active from historical threads. On success it removes only the registry entry, closes an idle App Server transport, retains the entire private `CODEX_HOME`, and records a bounded nonsecret removal audit entry. Profile and thread-owner writes share the gateway's cross-process `state.lock`; writes remain atomic. Labels are bounded/printable and rename rejects collisions.

`ModelCredentialStore` exposes `updateCredential(id, { label?, enabled? })`, `renameCredential(id, label)`, and `removeCredential(id)`. These use the existing `StateStore.update` lock and atomic persistence path. Removal deletes one encrypted credential record, leaves separate client tokens and other accounts intact, and records a bounded audit entry containing only the removed credential ID and timestamp. API key rotation remains separate; returned views omit secrets. Duplicate labels and unsupported fields are rejected for updates.

`renderCodexProfilesPage(profiles, snapshots, base)` now renders per-profile rename and remove forms. Root-owned route integration remains: pass the configured public base path as the third renderer argument; in the existing `/admin/codex/action` handler route `action=rename` to `renameProfile(id, label)` and `action=remove` to `removeProfile(id)`. Add an Ollama remove form to the Models & APIs account row and a CSRF-protected `/admin/models/remove` handler calling `removeCredential(id)`. The existing `withCsrf` wrapper injects the form token. The forms use the enclosing admin shell and existing styles; no `html.ts`, `ui.ts`, or `control-plane-admin.ts` route changes are included, so root integration should verify the four-column Codex table and compact forms in that shell.

Isolated tests set temporary `HOME` and `TOKEN2OAUTH_CONFIG_DIR` before constructing stores, exercise cross-process edits, and check Codex in-flight/login/thread guards, retained auth files, audit records, Ollama secret redaction, unrelated records, client-token preservation, and the rendered Codex forms. No real user profile or provider credential was read or changed.
