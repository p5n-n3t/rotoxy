## Contract for root wiring

Construct `CodexProfiles` with an absolute configured Codex executable path and absolute Token2OAuth config directory. The executable must be a regular executable file whose configured name is `codex`/`codex.exe`; the manager supplies only `app-server --stdio`, disables shell execution, and passes a minimal environment with a profile-specific `CODEX_HOME`. `registerProfile(label)` creates a random ID and mode-0700 directory; the mode-0600 `codex-profiles.json` contains only ID, label, directory, and timestamps. Registry capacity is 16 profiles and 8 concurrently running App Server processes; each process has bounded JSONL frames, request timeouts, and at most four in-flight requests. It never opens, parses, copies, emits, or deletes Codex credential files.

Use `listProfiles()`, `listSnapshots()`, `startDeviceLogin(profileId)`, `getDeviceLoginState(profileId)`, and `cancelDeviceLogin(profileId)` for explicit user actions. The login response is allowlisted to the official verification URL and device code; completion status is tracked in memory. After sign-in, call `refreshProfile(profileId)` for a filtered `account/read`, `model/list`, and `account/rateLimits/read` snapshot. Only returned rate windows are represented; missing quota stays unknown. `eligibleProfiles(modelId)` returns candidate IDs only and requires ChatGPT auth mode, a fresh exact model match, reported usage for every observed window, and no exhausted window. It never selects or rotates an account. Bind/resume with `bindThread(threadId, profileId)` and `profileForThread(threadId)`; a credential-free sidecar persists ownership. Call `close()` during root shutdown.

`renderCodexProfilesPage(profiles, snapshots)` returns escaped table markup only. Root must wrap it in the admin-session-protected page and add its own CSRF-protected, explicit actions. Do not expose profile directory paths, login IDs, account email/IDs, raw RPC messages, or credentials. Do not auto-enable profiles or claim subscription API access.
