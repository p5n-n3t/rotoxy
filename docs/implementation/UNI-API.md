# Unified model API checkpoint

Verified 2026-10-16. Cloudflare's official API reference documents the model catalog at [List models](https://developers.cloudflare.com/api/resources/ai/subresources/models/methods/list/) and inference at [Run model](https://developers.cloudflare.com/api/resources/ai/methods/run/); both pages returned HTTP 200 during this implementation. The existing `CloudflareAIAdapter` uses those fixed account-scoped routes. No undocumented provider route is used.

`createUnifiedModelApi(store, options?)` in `src/unified-model-api.ts` exports an Express router and the stores/adapter it composes. Root integration should mount `app.use(unified.router)` immediately before the existing model gateway. It handles only `GET /v1/models` and Cloudflare-prefixed `POST /v1/chat/completions`; all other paths continue downstream. `ollama/<model>` is rewritten to `<model>` in the request body before `next()`, while raw Ollama model IDs pass through unchanged. The existing gateway remains responsible for Ollama chat authorization and inference; no request is sent back to this server.

Both handled endpoints authorize the existing hashed model token with `model:read` or `model:invoke`. The catalog reports enabled Cloudflare credential allowlists as `cloudflare/@cf/...`; those are configured allowlists, not a claim that Cloudflare currently offers each model. It queries enabled, non-cooled-down Ollama credentials at the fixed `https://ollama.com/v1/models` endpoint, then includes both `ollama/<id>` and the raw ID alias. Catalog calls are read-only, bounded by the configured timeout, limited to 100 configured accounts and 256 KB per provider response, and never return credential labels or keys.

Cloudflare chat accepts bounded string-content system/user/assistant messages and optional `max_tokens`/`temperature`; it converts `result.response` into an OpenAI `chat.completion` and includes usage only when the provider reports it. SSE (`stream: true`) is explicitly rejected with 400. Tool calls, multimodal message content, and provider-specific response shapes are not converted. Inference is called once, with no retry; provider errors and bodies are not reflected. Serialized output is capped at 256 KB and completion text at 128 KB.

Focused evidence: `npm run build` and `node --test test/unified-model-api.test.mjs` pass (3 tests). Tests isolate `HOME` and `TOKEN2OAUTH_CONFIG_DIR` before constructing `StateStore`; they cover scope enforcement, merged catalogs and aliases, Cloudflare response conversion/output bounds, streaming rejection, sanitized ambiguous failure without replay, and pass-through/rewrite to the existing gateway. No server mounting change is included; root owns that integration.
