# Agent Workspace execution bridge

> **Status: bounded implementation complete.** Shared dispatch uses a separate owner/project namespace, stored owner membership is rechecked before shared projection, and uncertain submissions are reconciled with read-only owner-scoped calls. Do not interpret workspace task state as provider cancellation or as authorization to repeat a provider mutation.

`workspace_dispatch` and `workspace_sync` extend the existing OAuth-authenticated MCP surface. Both require `jobs:write`; neither accepts an actor, client, owner, account credential, or provider URL. The proxy derives the workspace actor from verified `client_id` claims and calls the existing `SupervisorBackend.authorizeWorkspace(projectId, clientId)` before any workspace operation. Dispatch validates one `JobSubmission` and passes it through the existing `backend.callTool("job_submit", ..., {projectId, clientId})` path after replacing only `jobId` and `idempotencyKey` with stable opaque hashes bound to project, OAuth owner, and caller-supplied values. This prevents a shared-publication collision from attaching an existing private job. Existing `job_submit` remains unchanged and private.

Dispatch records `(project, job, owner client, idempotency key, canonical request hash)` and the private submission in `agent-workspace.sqlite3` before calling the backend. The additive SQLite ledger is initialized by `supervisor/snooze/workspace_execution.py` using the existing Agent Workspace database path checks and SQLite locking. Replays with matching ownership/hash never submit again; a mismatched key/job/hash is rejected. Replayed calls avoid concurrent projection writes; if a process exits after provider acceptance but before all workspace metadata is projected, the owner can repair it through `workspace_sync`. A process death or error after reservation is treated as uncertain (`needs_reconciliation`), never as a signal to resend. `workspace_sync` first requires the caller's own ledger binding, then reads the existing owner-scoped backend routes; a status-read error remains `needs_reconciliation`, and a results-read error is returned as unavailable without changing the observed status. The sync response caps total result text at 512 KiB and marks truncated results.

Snapshots add at most 100 summaries (`projectId`, `jobId`, `state`, `provider`, `taskCount`, timestamps). They omit stored instructions and provider results. Because calling `workspace_dispatch` explicitly publishes that assignment to project collaborators, the gateway creates stable task metadata without copying prompts. Projected task and artifact identifiers are bound to project, verified dispatch actor, public job ID, and task ID, so two clients can use the same public job ID without sharing a ledger or task binding. A later owner `workspace_sync` may publish a bounded result excerpt as a pending text artifact. Full bounded result text is returned only to that owner by `workspace_sync`; longer shared excerpts say they are truncated. Membership is checked again after remote reads and before projection. Artifacts stay pending for independent review; the dispatch actor remains the task assignee and cannot approve their own artifact. There is no automatic approval, provider cancellation, merge, or completion inference. Unknown remote status remains `unknown`; only explicit provider task states/results affect workspace projection, and unsubmitted task/result rows are discarded.

The current Agent Workspace UI does not render the new `executionSummaries` field; MCP snapshots expose it immediately. The supervisor status DTO is reduced to bounded state/task identifiers and sanitized provider errors. Existing session/account selection and durable background workers remain owned by the supervisor; this bridge does not launch workers or invoke providers directly. If a dispatch outcome is ambiguous, an authorized caller must invoke `workspace_sync`; there is no background reconciliation loop in this increment.

Focused verification uses real temporary SQLite files and a fake `SupervisorBackend`; it exercises concurrent replay, restart-persistent intent, conflicting reuse, ambiguous no-resend, OAuth/project ownership, owner-scoped status/results, shared task/artifact projection, and the no-self-approval boundary. No live provider calls are part of the test.
