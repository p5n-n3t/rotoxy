# Agent Workspace execution bridge

> **Checkpoint status: incomplete.** This pushed checkpoint needs the follow-up hardening described below before it is considered finished: distinguish shared-dispatch idempotency from private job identity, retain and re-check the dispatching owner before projection, and ensure uncertain outcomes reconcile only through reads. Do not interpret workspace task state as provider cancellation or as authorization to repeat a provider mutation.

`workspace_dispatch` and `workspace_sync` extend the existing OAuth-authenticated MCP surface. Both require `jobs:write`; neither accepts an actor, client, owner, account credential, or provider URL. The proxy derives the workspace actor from verified `client_id` claims and calls the existing `SupervisorBackend.authorizeWorkspace(projectId, clientId)` before any workspace operation. Dispatch forwards the validated `JobSubmission` unchanged through `backend.callTool("job_submit", submission, {projectId, clientId})`; sync calls only the same backend's owner-scoped `job_status` and `job_results`. Existing `job_submit` remains private and unchanged.

Dispatch records `(project, job, owner client, idempotency key, canonical request hash)` and the private submission in `agent-workspace.sqlite3` before calling the backend. The additive SQLite ledger is initialized by `supervisor/snooze/workspace_execution.py` using the existing Agent Workspace database path checks and SQLite locking. Replays with matching ownership/hash never submit again; a mismatched key/job/hash is rejected. A process death or error after reservation is treated as uncertain (`needs_reconciliation`), never as a signal to resend. `workspace_sync` first requires the caller's own ledger binding, then reads the existing owner-scoped backend routes; a status-read error remains `needs_reconciliation`, and a results-read error is returned as unavailable without changing the observed status. The sync response caps total result text at 512 KiB and marks truncated results.

Snapshots add at most 100 summaries (`projectId`, `jobId`, `state`, `provider`, `taskCount`, timestamps). They omit stored instructions and provider results. Because calling `workspace_dispatch` explicitly publishes that assignment to project collaborators, the gateway creates stable task metadata without copying prompts, and a later owner `workspace_sync` may publish a bounded result excerpt as a pending text artifact. Full bounded result text is returned only to that owner by `workspace_sync`; longer shared excerpts say they are truncated. Artifacts stay pending for independent review; there is no automatic approval, merge, or completion inference. Unknown remote status remains `unknown`; only explicit provider task states/results affect workspace projection.

The current Agent Workspace UI does not render the new `executionSummaries` field; MCP snapshots expose it immediately. The supervisor status DTO is reduced to bounded state/task identifiers and sanitized provider errors. Existing session/account selection and durable background workers remain owned by the supervisor; this bridge does not launch workers or invoke providers directly. If a dispatch outcome is ambiguous, an authorized caller must invoke `workspace_sync`; there is no background reconciliation loop in this increment.

Focused verification uses real temporary SQLite files and a fake `SupervisorBackend`; it exercises concurrent replay, restart-persistent intent, conflicting reuse, ambiguous no-resend, OAuth/project ownership, owner-scoped status/results, shared task/artifact projection, and the no-self-approval boundary. No live provider calls are part of the test.
