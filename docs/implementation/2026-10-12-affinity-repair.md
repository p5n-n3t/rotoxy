# LightSprint session ownership repair

The public gateway now fails closed for an unknown `mcp-session-id`. A generic `/mcp` HTTP 200 is not account-ownership evidence, and an unknown session is never sent to a candidate credential or rebound from the response. A conflict between an established owner and a new upstream session ID returns 502 without forwarding that response. Known session follow-ups remain account-pinned; task-owner routing is unchanged.

`CredentialPool.registerSessionOwner(sessionId, accountId)` is the trusted registration seam. It validates bounded identifiers and returns the established owner on conflict without replacing it. Root runtime integration must validate each configured session/account binding and call this method before accepting MCP traffic, then reapply bindings after restart. Existing runtime config already carries registered session account IDs; root/runtime glue is outside this assignment.

The exact base has no `src/upstream.ts`; the native LightSprint status operation is in the account-pinned `LightSprintJobsAdapter` under `src/providers/lightsprint-jobs.ts`, outside this write scope. The public proxy has only `/mcp` and cannot safely use generic fan-out for native status reconciliation. Unregistered sessions therefore fail closed. If a future caller uses that native adapter, it may bind only after an accepted status DTO with `isOwner: true` from that exact account; `false`, 403, missing status, or ambiguity must leave ownership unset. Mutating or ambiguous requests must never participate in discovery or replay.

## Verification

New tests use a temporary `TOKEN2OAUTH_CONFIG_DIR`, synthetic accounts/tokens, and no live provider. They cover two distinct trusted owners, immutable registration, non-owner HTTP 200, unknown-session rejection without probing, 403 without failover, and an ambiguous mutation without replay. `npm run build` passed; the scoped Node tests passed 18/18, including routing-safety and OAuth regressions. `git diff --check` passed. A broader earlier run had one expected legacy failure in out-of-scope `test/integration.test.mjs`: it expects rediscovery of an unknown session to return 200. Root integration should update that case to register a trusted binding or assert the new fail-closed response. Full-suite checks were not rerun because unrelated tests may use operator-default storage.
