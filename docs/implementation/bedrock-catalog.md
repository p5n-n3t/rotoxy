# Bedrock catalog and model selection

Bedrock support is opt-in. With no saved operator settings, the Messages adapter continues to use the existing `ROTOXY_BEDROCK_REGION`, `ROTOXY_BEDROCK_TRANSPORT`, and `ROTOXY_BEDROCK_MODELS` environment configuration. The private `/admin/bedrock` page saves the selected region, endpoint (`invoke` for Bedrock Runtime or `mantle`), and enabled model IDs. An empty model selection denies invocation. Saved selections are loaded for each new request, so changing the selection takes effect immediately for later requests while a request already in flight completes under its original selection.

Catalog refresh is an explicit, read-only administrator action. Runtime discovery calls AWS `ListFoundationModels` filtered to Anthropic and paginated `ListInferenceProfiles` through the official AWS SDK. Mantle discovery calls its read-only `GET /v1/models` endpoint through the official Anthropic Bedrock Mantle client's authenticated GET method. The catalog retains Anthropic model IDs and inference profiles supported by this native Messages adapter. SDK retries are disabled. Requests time out, page counts and rows are capped, and the page shows when the cap truncated results. AWS credentials use the SDK's standard chain; ROTOXY does not read Claude settings files or persist credentials.

Catalog rows are discovery results only. Their entitlement and credit eligibility are recorded as `unknown`; listing a model does not establish account access or available credits. Refreshing never changes the enabled-model allowlist. `GET /providers/claude/v1/models` requires a ROTOXY `model:read` token and returns only operator-enabled IDs plus whether the source was administrator or environment configuration. It does not expose the full AWS catalog or assert entitlement.

The persisted non-secret settings and latest catalog snapshot live in `state.json`, written through `StateStore.update` using its private directory permissions and atomic replacement. If a persisted Bedrock settings record is malformed, the adapter fails closed instead of restoring environment allowlist access. The admin page uses the existing secure session and synchronizer CSRF token and requires the configured same-origin Origin on writes.
