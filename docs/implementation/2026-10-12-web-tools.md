## Contract

`src/web-tools.ts` exposes the `web_search` and `web_extract` definitions, `isToolName`, `requiredScope`, and `WebTools.call(name, args, caller)`. The caller must select exactly `exa`, `firecrawl`, or `tavily`; the module checks that provider's injected enabled/feature configuration and the injected per-client permission resolver before resolving a credential. It delegates input validation, SSRF-relevant URL constraints, response bounds, and provider-specific option validation to the existing adapters. One call invokes one selected adapter once. An ambiguous provider error is returned as a sanitized error and never triggers same-provider replay or cross-provider fallback.

Credentials and `fetch` are injected. Provider usage is returned separately as `providerUsage`, unchanged from the adapter response; unknown usage stays unknown, and this module does not estimate credits or prices. No credential is logged or persisted, and exact credential echoes in provider-controlled result fields are redacted before returning. Tests use mock fetch only; no live provider call or billing behavior has been verified.

## Root integration patch

Do not treat this module as exposed by the server yet. The root worker owns integration. The needed patch is:

1. In `src/server.ts`/`src/cli.ts`, construct and inject `WebTools` with an exact-provider config, a resolver that selects only the caller-authorized account for that same provider, and a per-client tool permission callback. Missing provider/account/capability must deny the call.
2. In `src/proxy.ts`, add `WEB_TOOL_DEFINITIONS` to OAuth-scope-filtered local discovery; reserve the two names; dispatch `web_search`/`web_extract` through `WebTools.call(name, arguments, claims.client_id)`; enforce `requiredScope`; and map `WebToolError` to sanitized MCP errors. Use default-deny client permissions.
3. In `src/types.ts` and `src/oauth.ts`, register `web:search` and `web:extract` as gateway scopes in the scope type, metadata, and authorization request allowlist. Do not grant either scope implicitly to existing clients.

The existing `StateStore.load()` and `revealToken(account)` provide a possible resolver boundary, but provider selection, client authorization, and enabling provider features are not configured by this module. `provider-capabilities.ts` inventories remote MCP surfaces; its snapshots alone do not prove that a REST credential is available or authorized for a local tool.

## Checks and limits

`test/web-tools.test.mjs` covers tool/scope exports, deny-before-credential behavior, exact feature/provider selection, provider-specific option passthrough, observed and unknown usage, credential non-leakage, and one-shot ambiguous failure. Run `npm run build && node --test test/web-tools.test.mjs`. The check level is **mock only** until a separately authorized real call; no new credentials or paid calls are part of this assignment.
