# Oracle model-admin maintenance controls

Branch `codex/rotoxy-oracle-maintenance-admin-20261017` is based on `origin/main` at `6703461229667b1bd6feb711748b9db12970bc46`.

This change extends `createOracleModelAdminRouter` with explicit owner-authenticated Pause dispatch and drain / Abort maintenance and resume actions. POSTs require same-origin and session CSRF, carry the displayed fleet config revision and exact expected integer epoch, and call only the fixed local Python bridge. The bridge holds the Oracle fleet config lock while checking its revision and invoking `OraclePool.request_maintenance(config_revision, expected_epoch)` or `release_maintenance(...)`. It does not change pool config, run systemctl, restart a service, or call any provider.

GET remains read-only: it never constructs `OraclePool` or initializes/recoveries database state. It calls the core-exported `read_maintenance_status(db_path)` helper, which reads the actual `pool_maintenance` and task tables with SQLite read-only/query-only settings. A missing helper, unsupported schema, or `ValueError` is rendered unavailable; the UI never assumes epoch zero. Maintenance writes use only `OraclePool.open_maintenance(db_path)`, the core's existing-state-only factory, and pass both `config_revision` and `expected_epoch` by keyword so request/release parameter ordering cannot be confused.

The UI distinguishes normal dispatch with no acknowledgement pending, paused/draining, paused/drained and acknowledged, and unresolved ambiguous work. Pause prevents new claims; it does not stop queueing, cancel tasks, or stop running tasks. Resume aborts maintenance and resumes dispatch without applying changes. Model APPLY remains preview-only because the restart/reload protocol has not been validated. The focused tests use temporary SQLite and fake callbacks, plus an integration test against the real core API when that API is present in the checked-out source. No live host, provider, or service calls are made.
