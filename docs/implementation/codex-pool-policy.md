# Codex worker pool policy foundation

`CodexPoolPolicyStore` adds a small, persistent operator policy around the existing local Codex profile registry. Its JSON sidecar contains profile IDs and scheduling preferences only. OAuth credentials remain within each profile's official Codex `CODEX_HOME`.

The initial policy has `dispatchEnabled: false`, enables each registered profile as a potential worker, and gives each profile `maxConcurrent: 1`. There is **no permanently primary account**. Every candidate lookup requires a resolved origin context containing the profiles used by that particular initiating client/session; those profiles are protected for that lookup only. Switching clients or accounts changes the protected set without editing global policy. An unresolved origin returns no automatic subscription candidates. An explicitly resolved client outside the registered pool may supply an empty protected set. MCP OAuth client IDs do not identify the native ChatGPT account; supporting clients must report their account binding, or the operator must configure it.

The policy reads only profile IDs from `codex-profiles.json` and serializes operations through `StateStore.update()`, which uses the gateway's shared `state.lock`. It writes atomically with mode `0600`; malformed or stale profile references fail closed. Newly registered profile IDs receive safe defaults the next time the policy is read or configured.

The candidate method accepts profile IDs already ranked by `CodexProfiles.eligibleProfiles()`, active assignment counts supplied by a scheduler, and the per-session origin context. It preserves that order and filters out global-off, protected, disabled, or at-capacity profiles. The activity map is required; omitted entries represent zero only when that map is the scheduler's complete authoritative ledger. The caller must never construct it from an incomplete observation.

`codexProfileFitsTask` separately checks snapshot freshness, known non-exhausted quota, exact model/effort compatibility and task complexity. Free profiles are restricted by local policy to routine work on Luna-class models. This restriction does not assert that model discovery establishes execution entitlement. It is an economical default for the operator's requested worker tiers. Capability and complexity are checked before quota ranking; percentages across accounts and provider families are never added into a supposed transferable balance.

This is policy storage and candidate filtering only. It does not reserve a worker slot, create or start Codex threads/turns, expose a dispatch API, refresh quota after restart, or reconcile interrupted execution. A durable scheduler must atomically claim the selected profile and persist the task-to-profile/thread/turn/model binding before reporting acceptance. Codex quota windows remain independent reported measurements; the policy does not add percentages across windows or infer remaining allowance.
