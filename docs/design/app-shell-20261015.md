# ROTOXY app-shell direction

The shell is for operators moving between gateway accounts, models, private workers, activity, and security settings. The existing ivory/teal relay mark and measured operator tables suit a persistent control surface better than a promotional hero or card dashboard.

## Two layout sketches

**A — fixed workspace rail (selected)**

```text
┌───────────────┬──────────────────────────────────────────────┐
│ ROTOXY        │ Current page: Supervisor                     │
│ workspace     ├──────────────────────────────────────────────┤
│ Command       │                                              │
│  Overview     │ Existing server-rendered page content         │
│  Jobs         │                                              │
│  Supervisor   │                                              │
│ Resources     │                                              │
│  Accounts     │                                              │
│  Models       │                                              │
│  ...          │                                              │
│ Insights      │                                              │
│ Settings      │                                              │
└───────────────┴──────────────────────────────────────────────┘
```

**B — grouped top navigation**

```text
┌──────────────────────────────────────────────────────────────┐
│ ROTOXY · Workspace     Command  Resources  Insights  Settings│
├──────────────────────────────────────────────────────────────┤
│ Current page: Supervisor                                      │
│ Existing server-rendered page content                         │
└──────────────────────────────────────────────────────────────┘
```

Option A keeps the four groups and current location visible without using a second horizontal navigation row or compressing page content. On narrow screens its same navigation becomes a native, keyboard-operable details drawer. The main content retains its existing server-rendered width and markup.

## Visual tokens

- Rail: `#173A37`; rail text: `#EDF4EF`; active teal: `#28524C`.
- Canvas: `#F3F4EF`; content surface: `#FFFEFA`; separators: `#D8DDD5`.
- Signal: `#0F7B6C`; focus: `#D4832F`.
- Typography: Inter with system UI fallbacks; compact 13px navigation, 14px current-page label, and inherited page type scale.
- Alignment: workspace and section labels align to one left edge; route labels stay left aligned; long names wrap instead of clipping.

## Route audit

Links point only to existing HTML pages: Overview and Activity use `/admin` (the overview contains recent request activity); Workspace accounts uses the real `#accounts` section; Supervisor uses `/admin/supervisor`; Models and Clients use `/admin/models` (client tokens are managed on that page); Private workers uses `/admin/oracle`; Search uses `/admin/resources`; Auth uses `/admin/security`; Diagnostics uses `/admin/diagnostics`. The current server exposes no standalone Jobs or Analytics HTML pages, so these labels are visible but inert rather than pointing at invented routes. Analytics exists as an authenticated JSON API only.

The existing shell is emitted from `src/html.ts`, which is outside this assignment's file scope. This module is a tested drop-in wrapper for root to wire into that shared page renderer; no existing page, route, form, auth middleware, or persisted state is changed here.
