# Agent Workspace UI handoff

`renderAgentWorkspace(snapshot, { base, csrfToken, projects, projectId })` renders the authenticated `/admin/agents` page in the existing shared page shell. It uses the AW1 snapshot only: reported participants, task states, messages, artifacts, reviews, event metadata, and revision. Collections are capped at 100 (dependencies at 16); displayed labels and user-authored text are allowlisted, bounded, escaped, and passed through known-secret redaction. A snapshot whose `projectId` does not match the selected registered project renders no project records.

The page offers the 4-column Queued / Working / Review / Done board, with blocked tasks tagged within Working; participant attribution; project selection; compact Inbox, Artifacts & Reviews, and Activity panels; and native keyboard-accessible forms. No JavaScript, provider sends, external fetches, fake metrics, or client-supplied actor field are used. The shared `withCsrf` helper adds `_csrf` to every POST form. Each update includes `expectedRevision` and a generated `idempotencyKey`.

Root integration seams: mount this renderer at `GET /admin/agents?project=...`, expose the AW1 authenticated update endpoint at `POST /admin/api/v1/agent-workspace/:projectId/update`, parse URL-encoded fields into the action input, and supply the verified boundary actor. `task_create.dependsOn` is rendered as comma-separated IDs for the adapter to split into an array; the UI does not select or impersonate an actor. Add the Agent workspace primary navigation entry and label the existing `/admin/workspace` resource canvas “Resources”. The view has no live refresh; the route should fetch a fresh authorized snapshot on navigation.

Verification on the isolated branch from `origin/main` `2c0bc90`: `npm run build` passed; `node --test test/agent-workspace-ui.test.mjs` passed all 5 tests. Tests cover workflow/action rendering, CSRF/revision/idempotency fields, HTML and secret redaction, project isolation, collection bounds, responsive layout, and reduced motion. The Impeccable Operate/Craft skill was not present in the available workspace skill directory, so the existing shared shell and Jobs/Supervisor UI were used as design references. No server route was mounted or live page captured in this renderer-only change.
